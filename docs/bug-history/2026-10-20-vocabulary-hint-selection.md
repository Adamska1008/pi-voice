## 背景与现象

动态词表已能随话题更新，但也收录常见技术词，以及仅来自引用链接的标识符。
预期词表优先帮助 ASR 识别特殊拼写，而不是列出对话里所有技术概念。
本记录只使用通用示例描述问题，不保存原始会话、实际词表或运行日志。

## 定位过程与根因

1. 检查 `src/vocabulary-background.ts`：原指令要求提取专名、技术词和代码标识符，
   虽然要求排除普通词，但没有区分“技术话题关键词”和“值得提示 ASR 的词”。
2. 检查 `src/conversation-context.ts`：正文过滤会去掉围栏代码，但保留 Markdown 链接；
   URL 中的作者名和路径也可能被模型视为候选。
3. 检查 `src/vocabulary-cache.ts`：缓存只负责按真实提及位置刷新、排序和淘汰，
   不判断词的听写价值。因此此次修改准入提示词，不改 LRU 或增加评分层。

以上确认了指令和处理链路；具体词对 ASR 准确率的收益尚未测量。

## 修复方法

- `src/vocabulary-background.ts`：明确任务是选择 ASR 拼写提示，不是话题摘要。
- 优先特殊专名、项目名、型号、专业缩写、代码标识符和用户明确纠正的拼写。
- 默认跳过常见中英文词和常规技术词；对话明确指出识别/拼写问题时允许例外。
- 跳过只存在于 URL 或引用元数据中的作者名、文件名和路径片段；正文独立讨论时可选。
- 明确不凑满 32 个，无合适词返回空数组；保留原文拼写和仅输出 JSON 的约束。
- 不增加请求次数、模型复审、黑名单或缓存迁移；不改固定词表、调度和解析逻辑。
- prompt 比原先略长，因此每次请求输入开销略增；未测量实际 token 增量。

## 真实复测步骤

1. `/reload` 加载新 prompt；使用全新会话隔离旧缓存，不删除原会话数据。
2. 用合成对话同时包含特殊项目名、常规技术词及只在引用 URL 中出现的路径。
